# 협업 흐름

## 브랜치와 리뷰

main은 릴리즈만, develop은 통합 개발, feature/기능명은 기능 개발에 사용합니다.
기능 브랜치는 최신 develop에서 만들고 완료하면 develop으로 PR을 생성합니다.
최소 1명 승인 후 PR로 병합합니다. 릴리즈도 develop → main PR로 진행합니다.
main/develop 직접 푸시는 금지합니다.

현재 원격에는 main만 있습니다. 이번 로컬 develop은 그 기준 커밋을 가리키며 원격 브랜치가 아닙니다.
저장소 관리자가 GitHub에서 main 기준 develop을 초기 생성한 다음 아래 보호 설정을 적용해야 합니다.
이는 기능 변경의 직접 푸시나 병합을 뜻하지 않습니다.

- main/develop: PR 필수, 승인 1명 이상, 새 커밋 시 기존 승인 무효화.
- 강제 푸시·삭제 금지, 가능한 경우 우회 권한도 제한.
- GitHub 보호 설정은 관리자 권한이 필요하며 이번 로컬 작업에서는 적용하지 않았습니다.

로컬 훅 활성화: `git config core.hooksPath .githooks`.
commit-msg는 제목 형식을, pre-push는 보호 브랜치 및 feature 이름을 검사합니다.
로컬 훅은 우회 가능하므로 서버 보호 규칙을 대신하지 않습니다.

## 커밋 헤더

| 헤더 | 용도 |
| --- | --- |
| [TEST] | 테스트 코드 |
| [MERGE] | PR 병합 관련 |
| [BUILD] | 빌드 관련 |
| [INIT] | 프로젝트 초기 설정 |
| [DOC] | 주석·문서 수정 |
| [REFAC] | 리팩토링·파일 구조 수정 |
| [FIX] | 버그 수정 |
| [MOD] | 기존 기능 수정 |
| [ADD] | 에셋·씬 등의 단순 추가 |
| [FEAT] | 새 기능 구현 |

예: `[REFAC] 전투 필드명과 오브젝트 이름을 팀 규칙에 맞게 정리`.
GitHub에서 squash/merge할 때도 자동 생성 제목을 그대로 쓰지 말고 위 헤더를 적용합니다.

## 씬과 에셋

현재 전투 씬은 런타임 생성 구조입니다. 이번 정리는 씬 파일을 재저장하거나 프리팹으로 전환하지 않습니다.
향후 동일 씬을 여러 명이 수정하면 기능 오브젝트를 Prefab_이름으로 분리해 전달하고 필요한 위치에서 unpack합니다.
기존 씬 파일명과 공유 폰트 리소스 키는 참조 호환을 위해 유지합니다. 새 오브젝트와 데이터 에셋부터 형식_이름 규칙을 적용합니다.
C# 파일은 Unity 클래스명과 일치하도록 PascalCase를 유지합니다.

## 인수인계와 검증

메서드 안내를 읽고 수정한 경로의 호출부를 확인합니다.
`CombatChecks.Run`은 전투 회귀 및 CSV 검사를 수행합니다. 자동 검사는 실제 조작감 검증을 대신하지 않습니다.
PR 본문에 검사 결과와 미확인 사항을 적고 스프린트 작업표를 갱신합니다.
